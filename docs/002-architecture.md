# 整体架构设计

## 核心决策

**独立的本地服务进程 + 编辑器薄插件层**。一套后端服务同时支持所有编辑器。

设计原则：
- 模型推理逻辑集中在一个进程，GPU 资源管理简单
- 编辑器插件极薄（几百行代码），跨平台移植成本低
- 可以轻松切换后端模型（本地 / 远程 / 混合）

## 编辑器插件职责

每个编辑器插件只做三件事：

1. **采集编辑事件**：监听 `textDocument/didChange`，发送给 next-edit-server
2. **渲染建议**：接收 `nextEdit/suggest` 通知，渲染为 inline diff
3. **处理交互**：`Cmd+;` 接受建议，`Esc` 拒绝

## 服务进程职责

- 维护编辑历史状态（滑动窗口，保留最近 3 次编辑的 diff 序列）
- 运行 Location Module 确定编辑位置
- 运行 Generation Module 生成代码修改
- 管理模型加载 / 卸载 / 推理资源

## 模型组件

| 组件 | 用途 | Phase 1 方案 | Phase 2+ 方案 |
|------|------|-------------|--------------|
| Location Module | 预测下一编辑位置 | tree-sitter AST 规则 | fine-tuned retriever (UniXcoder / CodeBERT) |
| Generation Module | 生成代码修改 | Qwen2.5-Coder-7B few-shot | SFT + DAPO fine-tuned model |
| Description Module | 生成修改说明（可选） | 不实现 | 1.5B 小模型摘要 |
